# ЮKassa: полный тест подписки и автопродления

Дата проверки: 2 августа 2026 года.

Проверка выполнена в production-контуре Kaigo с тестовым магазином ЮKassa и
официальной тестовой картой. Реальные деньги и боевые платёжные данные не
использовались. Для проверки создан отдельный синтетический пользователь без
доступа к проектам реальных пользователей.

## Что проверено

1. Kaigo создал новый checkout тарифа `starter_monthly` на 1 990 ₽ с явным
   согласием на автопродление.
2. Страница ЮKassa показала тестовый режим, сумму и предупреждение об
   автосписаниях.
3. Оплата официальной тестовой картой завершилась успешно.
4. Webhook или серверная reconciliation перевели внутреннюю попытку в
   `succeeded`.
5. Создана активная подписка, сохранён способ оплаты и включено
   `auto_renew=true`.
6. Начисление лимита и платёжное событие записались ровно по одному разу.
7. Принудительно наступивший тестовый срок продления создал один повторный
   платёж через сохранённый способ без участия пользователя.
8. Повторный платёж завершился `succeeded`, период подписки продлился, второе
   начисление появилось ровно один раз.
9. После отключения автопродления подписка осталась активной, оплаченный период
   не сократился, сохранённый способ получил статус `disabled`, а повторный
   запуск scheduler не создал новый платёж.

## Обезличенные результаты

```text

initial credits: 1

renewal attempt number: 1

saved payment method after disable: disabled
new attempts after disable: 0
```

## Вывод

Для тестового магазина доказан полный цикл:

`redirect checkout → succeeded → сохранённый способ → автопродление →
продление периода → отключение автопродления`.

Боевой запуск по-прежнему требует отдельной проверки настроек настоящего
магазина, чеков и юридических данных. Тестовые секреты хранятся только в
окружении сервера и в этот отчёт не включены.
