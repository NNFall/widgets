## Что изменено

При `max_pages=1`, как в production-пайплайне Kaigo, desktop- и mobile-
viewport теперь снимаются одновременно. Внутри каждого viewport сохранена
прежняя последовательность: загрузка, пауза, полный прогревочный скролл,
возврат наверх и кадры top/middle/bottom. Ограничения URL, robots.txt,
таймауты, byte budget и retry не ослаблены.

Локальный A/B-замер того же сайта:

- до изменения: `51,802 с`;
- после изменения: `30,504 с`;
- экономия: `21,298 с` (`41,1%`) при тех же шести кадрах.

На production-сервере во время параллельного захвата worker использовал около
`327 МБ` памяти из `1,922 ГБ`, поэтому ускорение не создало опасного пика.

## Дополнительная исправленная ошибка

Во время проверки обнаружено, что повтор старого запуска мог вернуть уже
существующий, но больше не активный replacement-run по прежнему
`Idempotency-Key`. Backend теперь возвращает `409 run_is_not_active`, если
найденный idempotent replay уже не является активным запуском проекта. Это
исключает смешивание статусов разных запусков в Studio.
