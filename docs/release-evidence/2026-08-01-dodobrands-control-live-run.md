## Что проверено

Полный пользовательский путь был выполнен от имени отдельного подтверждённого
тестового пользователя в production PostgreSQL: авторизованная серверная сессия,
создание проекта через HTTP API, резерв бесплатной генерации, durable worker,
семь этапов сборки, создание пяти проверенных ревизий, browser gate, три
независимых визуальных критика, независимый судья и финальное списание trial.

Визуальная проверка сняла шесть кадров: desktop и mobile в закрытом состоянии,
при первом открытии и после двух ходов диалога. Судья принял результат с первой
визуальной попытки. Встроенный браузер Codex отдельно открыл публичную ревизию и
успешно нажал launcher; DOM подтвердил заголовок, статус, приветствие, две быстрые
кнопки, поле ввода и отправку.

Живой owner-scoped чат также проверен через production API. На вопрос «Какие
бренды развивает Dodo Brands и как стать партнёром?» сервер вернул HTTP 200 и
назвал Dodo Pizza, Drinkit и действие `Become partner`, не выдумывая отсутствующие
в подтверждённых данных условия.

## Исправления, сделанные по ходу прогона

1. Для основных прямых Gemini-этапов добавлена вторая route-попытка при временном
   `provider_unavailable`. Это устраняет падение всей длинной сборки из-за одного
   краткого отказа провайдера.
2. В prompt добавлены точные allowlist разрешённых HTML-элементов и атрибутов,
   совпадающие с детерминированным валидатором. До исправления identity-этап
   повторно создавал `forbidden_element` и `forbidden_attribute`; после исправления
   этот этап прошёл без repair-вызова.

## Честная визуальная оценка

Виджет уже читается как настоящий компактный чат: роли разведены по сторонам,
размер desktop разумный, на mobile остаются безопасные поля, ввод и основные
действия доступны. Палитра и оранжевый акцент узнаваемо связаны с Dodo.

При этом результат пока не выглядит уникальным премиальным «AI-сотрудником»:
аватар и геометрия достаточно стандартны, а мобильная панель занимает заметную
часть экрана. Кадры browser gate снимают виджет на нейтральной сцене, а не поверх
реальной страницы Dodo Brands. Это не блокирует функциональную проверку, но
интегрированный screenshot поверх исходного сайта должен стать отдельным
визуальным критерием.

## Следующая оптимизация

Главный резерв времени — reference crawl. В этом прогоне анализ сайта занял около
семи минут при нулевой модельной стоимости, а retry предыдущего запуска повторял
тот же crawl целиком. Следующий шаг: контентно-адресуемый кэш скриншотов и
`reference_context`, а также возобновление retry с последней проверенной ревизии.
После этого имеет смысл оптимизировать дорогие генеративные роли и визуальный
комитет.
