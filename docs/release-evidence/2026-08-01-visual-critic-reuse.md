# Повторное использование успешных визуальных критиков

Статус: реализовано и проверено локальными тестами; контрольный production-прогон выполняется отдельно.

## Что изменено

- При повторной AI-проверке тех же браузерных кадров повторно вызываются только критики, которые не дали успешного результата.
- Успешные ответы сохраняются только внутри текущего визуального gate и только для того же неизменяемого объекта аудита, того же brief и того же арт-направления.
- Новые снимки, изменение brief или арт-направления полностью сбрасывают кэш.
- Независимый судья вызывается на каждой попытке, поэтому quorum и fail-closed поведение не ослаблены.
- В forensic-событии `visual_critic.completed` теперь явно записывается `reused: true|false`, а пользовательское сообщение сообщает об использовании сохранённого результата.

## Проверка

```text
python -m pytest -q tests/builder_lab_cases/test_visual_committee.py tests/builder_lab_cases/test_visual_repair_gate.py tests/builder_lab_cases/test_visual_review.py
62 passed

python -m ruff check builder_lab/visual_committee.py builder_lab/visual_gate.py tests/builder_lab_cases/test_visual_committee.py tests/builder_lab_cases/test_visual_repair_gate.py
All checks passed!
```

TDD-сценарий подтверждает:

- два успешных критика вызываются один раз;
- сбойный критик вызывается повторно;
- судья вызывается повторно;
- при новом аудите снова вызываются все три критика;
- расход prompt-токенов тестовой повторной попытки уменьшился с 53 до 30, то есть на 43,4%.

## Оценка на реальном Simple Coffee

В контрольном запуске Simple Coffee второй комитет повторно вызвал три уже успешные роли. Эти вызовы стоили суммарно `$0.049732` и заняли до `28.8` секунды параллельного ожидания. Новый механизм должен исключить именно этот повтор при неизменных кадрах. Это расчёт по сохранённой телеметрии, а не заявление о уже измеренном production-ускорении.

## Границы

- Результаты не сохраняются между процессами или разными запусками.
- Кэш не применяется после ремонта виджета и нового браузерного аудита.
- Неуспешные ответы никогда не кэшируются.
- Экономия зависит от числа повторных попыток визуального судьи.
