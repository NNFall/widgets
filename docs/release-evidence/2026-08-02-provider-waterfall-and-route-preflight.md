# Provider waterfall и production preflight

Дата: 2026-08-02

## Что опубликовано

Защищённая операторская временная шкала запуска теперь содержит безопасный
`model_waterfall`: этап, логический вызов, последовательность fallback-попыток,
целевые и фактические provider/model, статус, задержку, usage, стоимость и
нормализованный `error_code`.

Сырые ответы провайдера, prompt, API-ключи, request id, pricing-файлы и
`error_message` в операторский контракт не попадают. Неизвестный код сбоя
сворачивается до безопасного `provider_error`.

Операторский список доступен после входа разрешённым OAuth-аккаунтом:

- <https://kaigo.space/operator/generation-runs>

## Production-проверка

- Backend после пересборки отвечает `{"status":"ok"}`.
- Главная и Studio открыты во встроенном браузере после deploy.
- Waterfall прочитан из production PostgreSQL новым кодом.
- Последний успешный run `a1e23b39-bf4d-4f39-bc60-2a5a7b1a74a6` показывает
  завершённые вызовы `gemini-3.5-flash-lite` по всей цепочке.
- В историческом run `8bc5b326-3511-4cd4-ba1c-62c75250cb8d` waterfall явно
  показывает повторные `provider_unavailable` для `agentrouter/gpt-5.5` и
  `agentrouter/glm-5.2`.

## Текущий preflight маршрутов

Однократный минимальный запрос из production worker дал:

- AgentRouter: `provider_permission_denied`;
- ZenMux DeepSeek V4 Flash Free: `provider_permission_denied`;
- production hybrid routing остаётся выключенным, поэтому эти недоступные
  маршруты не замедляют пользовательскую генерацию;
- рабочий Gemini-маршрут остаётся активным.

Код не может исправить права внешнего кабинета. Для включения GPT-5.5, GLM-5.2
или DeepSeek нужен действующий credential/баланс, после чего достаточно одного
короткого preflight и переключения существующего feature flag.

## Измерение последнего полного прогона

Суммарное wall time этапов последнего успешного запуска — примерно 275 секунд.
Самый дорогой этап — `motion_polish` (около 104 секунд). Повторная тройка
визуальных критиков из старого запуска израсходовала около 41 тыс. токенов.
Исправленный валидатор был отдельно переигран на сохранённых снимках: все три
критика и судья прошли с первой попытки, поэтому этот повтор не должен
возникать в новых запусках с тем же классом корректных отчётов.
