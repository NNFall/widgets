# Kaigo — старт для Telegram-редактора

Этот файл — единственная обязательная точка входа для отдельной задачи
«Kaigo — Telegram-редактор».

## Что такое Kaigo

Kaigo анализирует содержание и визуальный язык сайта и создаёт индивидуального
AI-сотрудника: компактный брендовый чат, который отвечает посетителям по
информации бизнеса. Долгосрочное направление — AI-слой поверх сайта, способный
понимать контекст страницы и предлагать релевантную помощь.

Центральная человеческая формулировка:

> Через несколько минут вы сможете показать клиентам: наш бизнес использует AI.

Не обещай конкретные пять минут как текущий факт: последний подтверждённый
полный прогон занял 14 минут 32 секунды.

## Текущее состояние

- Работает staged-генерация из пяти видимых ревизий.
- Основной генератор, анализатор сайта и визуальные критики используют
  Gemini 3.6 Flash с высоким уровнем thinking.
- Чат посетителя использует Gemini 3.5 Flash Lite с уровнем thinking medium.
- Генерация анализирует публичный сайт, создаёт desktop/mobile виджет и
  проверяет реальный двухходовый диалог.
- Визуальную проверку выполняют три специализированных критика и независимый
  судья; допускается кворум двух валидных ответов.
- Текущий запуск восстанавливается после обновления страницы.
- Последний рабочий черновик остаётся видимым при незавершённой проверке.
- Последний подтверждённый прогон Flowwow завершился со статусом `verified`.
- Новый публичный сайт Kaigo из восьми экранов развёрнут на
  <https://kaigo.space/> и проверен на desktop/mobile.
- Визуально согласованная Studio доступна по `/studio`, но пока закрыта
  существующей Builder Basic Auth.

Публичная демонстрация: <https://kaigo.space/builder-demo/>

Перед добавлением ссылки в пост проверь, что она открывается извне.

## Порядок работы редактора

1. Выбери тему со статусом `ready`.
2. Открой связанный release packet и доказательства.
3. Отдели выпущенные возможности от планов.
4. Подготовь один основной текст и при необходимости короткую альтернативу.
5. Укажи, какие изображения нужны и в каком порядке.
6. Сохрани черновик в `drafts/` со статусом `review`.
7. Не публикуй его и не меняй `published.jsonl` без явного подтверждения
   владельца проекта.

Если журнал и код расходятся, остановись и попроси техническую задачу уточнить
факт. Не достраивай историю самостоятельно.
