# Экспериментальный AntiGravity-провайдер для Kaigo Builder

Дата: 2026-08-17

Статус: код реализован и проверен локально; production-включение и публичный
URL-to-widget прогон не выполнены.

## Коротко

Kaigo подготовлен к безопасному эксперименту с AntiGravity на раннем этапе
генерации. Новый путь выключен по умолчанию и сохраняет Codex как fallback, но
live-проверка остановлена до исправления лицензии OAuth-аккаунта провайдера.

## Что было раньше

- Три варианта первого направления создавались через один существующий
  Codex-маршрут.
- Развёрнутый AntiGravity API ещё не был подключён к общему ModelRouter Kaigo.

## Что изменилось

- Добавлен отдельный текстовый адаптер к `/antigravity-api/v1/respond` с
  проверкой JSON Schema, нормализацией usage и безопасным отображением ошибок.
- Контракт учитывает восстановленные upstream-ответы, где заполнен только
  `total_tokens`: итог проверяется, но не используется для выдуманного billing-
  распределения по input, output и thinking.
- При включённом экспериментальном флаге только три параллельных
  `direction_candidate` сначала обращаются к AntiGravity
  `gemini-3.7-flash-high`, затем при допустимой ошибке — к Codex.
- Судья направлений, генерация HTML, repairs, анализ изображений, визуальные
  критики и публичный чат сохраняют прежние маршруты.
- Конфигурация fail-closed: HTTPS, ключ, модель, reasoning effort и Codex-
  fallback обязательны; по умолчанию новый маршрут выключен.
- Локально реализовано неизменяемое поколение egress-правил G5. Оно разрешает
  TCP 443 только от фиксированного builder worker `/32` к одному NL gateway
  `/32`; соседний builder-lab не наследует это исключение. Неполное, изменённое
  или дополнительно подключённое поколение отклоняется без мутации firewall.
- Настройки и bearer-секрет AntiGravity вынесены из общего окружения в отдельный
  обязательный `builder-worker-antigravity.env`. Systemd проверяет владельца
  `root` и mode 600 до старта worker.

## Проверенные факты

- Финальный targeted-прогон провайдера, конфигурации, роутинга, направлений,
  deployment и egress-контрактов: 240 passed, 12 skipped.
- Отдельная Linux-проверка state machine egress guard: 17/17 сценариев.
- Публичный gateway принял bearer-авторизацию и передал запрос провайдеру, но
  оба проверенных модельных маршрута завершились HTTP 502 `provider_failed`.
- Прямой запуск CLI на US-хосте вернул точную причину: у текущего
  OAuth-аккаунта нет действующей лицензии продукта (`#3501`).
- API-ключи, OAuth-токены и адреса серверного доступа в репозиторий и этот
  пакет не добавлены.

## Ограничения

- AntiGravity пока не включён в production-конвейере Kaigo.
- Локально подготовленные systemd, secret-env и G5 egress-правила ещё не
  установлены на production-хосте.
- Успешный реальный structured turn через US-провайдер не подтверждён.
- Генерация виджета из чистого URL, публикация, внешний loader и чат с новым
  маршрутом ещё не проверены.
- Пакет нельзя использовать как доказательство готового production-релиза.

## Следующий проверочный gate

1. Авторизовать на US-хосте аккаунт с действующей лицензией AntiGravity.
2. Получить успешный structured smoke через публичный endpoint.
3. Установить проверенные systemd, root-only secret-env и неизменяемое G5-
   поколение, затем включить флаг только для builder worker.
4. Проверить provenance трёх кандидатов и отсутствие AntiGravity в остальных
   ролях.
5. Пройти полный canary: URL сайта, готовый виджет, публикация, внешний loader,
   адаптивность, чат, allowed origin и rollback.
