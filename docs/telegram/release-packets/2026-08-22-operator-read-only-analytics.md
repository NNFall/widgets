# Как Kaigo сам читает свою воронку

Дата: 2026-08-22

Статус: реализовано локально и покрыто тестами; production rollout ожидает
штатного выпуска app/static release и установки root-only секрета.

## Коротко

Чтобы анализировать первые рекламные запуски без ручного входа во встроенный
браузер, в Kaigo добавлен отдельный read-only контур. Он не создаёт нового
пользователя и не выдаёт доступ к базе: автоматизация получает только уже
агрегированные отчёты.

## Что доступно

- воронка за период с фильтром по источнику;
- последние санитизированные запуски генератора;
- сводная команда `snapshot`, объединяющая оба отчёта.

Сервисный bearer-токен принимают только JSON read routes. HTML, публикация,
биллинг, админские операции и сырые IP, email, URL, prompt или provider payload
остаются недоступны. Секрет не пишется в Git, URL, логи или сообщения.

## Проверка

Локально прошли 60 тестов нового и затронутого маршрута, 99 config/deployment
тестов и Ruff. Production пока не изменялся: после выпуска нужно положить
случайный 32+ byte секрет в root-only secret store, перезапустить app по
runbook и проверить CLI на `--source yandex`.

## Возможный сюжет

Когда в Директе появятся клики, можно одной командой сравнивать рекламный
источник, путь до Studio и запуски генератора. При этом сервис не пытается
выдать точное число людей по IP и не превращает read-only ключ в пароль от
админки.
