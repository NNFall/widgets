# Публичная демонстрация Kaigo Builder

## Цель

Открыть Kaigo Builder на существующем HTTPS-домене без SSH, сохранить
интерактивный результат реальной генерации между перезапусками и не дать
посторонним расходовать Gemini-баланс.

## Публичные адреса

- `https://kaigo.space/builder-demo/` — открытая демонстрационная страница.
  Она показывает исходный запрос, модель, режим, длительность, токены и
  интерактивный финальный виджет. Запускать модель с этой страницы нельзя.
- `https://kaigo.space/builder/` — полный Builder Lab. Доступ защищён HTTP
  Basic Auth на уровне nginx. После входа работают генерация, SSE-журнал,
  отмена, повтор и все промежуточные preview-ревизии.

`kaigo.online`, корневой маршрут `kaigo.space`, production API, база и
существующие виджеты не меняются.

## Изменения приложения

1. Все browser API-адреса Builder Lab становятся относительными. Поэтому одна
   и та же страница работает как в корне локального сервиса, так и под
   префиксом `/builder/` за nginx.
2. Добавляются read-only маршруты `/demo` и `/demo/preview`.
3. Демо загружается из JSON-файла, путь к которому задаётся конфигурацией.
   Перед показом артефакт повторно проходит штатную детерминированную
   валидацию. Повреждённый или небезопасный файл не рендерится.
4. Smoke-скрипт получает параметр сохранения: после успешного реального
   `run.completed` он атомарно записывает только безопасные метаданные и
   финальный артефакт. Ключи, заголовки авторизации и provider diagnostics в
   файл не попадают.
5. Каталог демо подключается к контейнеру отдельным bind mount и переживает
   сборку или перезапуск контейнера.

## nginx и защита

- `/builder/` проксируется на `127.0.0.1:8091` с удалением префикса и
  обязательным Basic Auth.
- `/builder-demo/` и `/builder-demo/preview` проксируются только на два
  read-only маршрута демо без пароля.
- Порт `8091` остаётся опубликован только на loopback; наружу напрямую он не
  открывается.
- Пароль генерируется случайно, хранится только в серверном htpasswd-файле и не
  попадает в Git.

## Проверка

- Автотесты подтверждают относительные API-адреса, безопасную загрузку демо,
  отказ при повреждённом артефакте и отсутствие секретов в экспорте.
- Полный набор тестов, `compileall`, `pip check` и `git diff --check` должны
  пройти до публикации.
- После deployment выполняется новая реальная staged-генерация Gemini с
  сохранением результата.
- Playwright проверяет оба публичных URL, Basic Auth, интерактивность launcher,
  desktop/mobile и отсутствие ошибок консоли.
- Отдельно повторно проверяются корень production, `/w/demka`, база, nginx и
  отсутствие изменений на `kaigo.online`.
