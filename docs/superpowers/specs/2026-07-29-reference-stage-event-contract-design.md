# Контракт события завершённого анализа сайта

## Проблема

Durable worker формирует событие `reference.completed` после успешного анализа
исходного сайта, но `StageResult` разрешает только `repair.completed`. Поэтому уже
полученный и оплаченный результат провайдера отклоняется локальной валидацией с
ошибкой `stage result event type is not allowed`, а повторный запуск того же
provider dispatch намеренно блокируется защитой от двойного списания.

## Решение

- Сохранить строгий белый список событий `StageResult`.
- Добавить в него существующее штатное событие `reference.completed`.
- Зафиксировать контракт отдельным регрессионным тестом.
- Не менять маршрутизацию моделей, retry/reconciliation и формат событий.

## Проверка

1. До исправления тест должен воспроизводить точную ошибку контракта.
2. После исправления тест и весь набор тестов worker должны проходить.
3. В production worker должен содержать новый контракт и оставаться активным.
4. У тестового пользователя должна быть доступна одна бесплатная генерация.
