# Редакторский контур Telegram для Kaigo

Дата: 26 июля 2026 года

Статус: согласовано пользователем

## Цель

Отделить техническую разработку Kaigo от подготовки публикаций, не теряя
проверяемую историю продукта. Основная задача Codex продолжает разработку, а
отдельная постоянная задача «Kaigo — Telegram-редактор» получает короткие
пакеты значимых изменений из репозитория.

## Архитектура

Репозиторий является устойчивым мостом между двумя задачами:

1. `docs/product-journal/` хранит хронологию проверенных изменений.
2. `docs/telegram/release-packets/` переводит технический результат на язык
   будущей публикации.
3. `docs/telegram/content-backlog.md` хранит идеи и приоритеты постов.
4. `docs/telegram/drafts/` хранит тексты до утверждения владельцем проекта.
5. `docs/telegram/assets/` описывает и связывает визуальные доказательства.
6. `docs/telegram/published.jsonl` защищает канал от повторной публикации.

Корневой `AGENTS.md` требует обновлять редакторский контур после значимого
результата. Отдельные команды, промежуточные догадки, секреты и внутренние
адреса в публичный контур не попадают.

## Значимое изменение

Запись обязательна, если произошло хотя бы одно из событий:

- появился или заметно изменился пользовательский сценарий;
- обновление развёрнуто и проверено;
- завершился показательный прогон генерации;
- изменились модели, архитектура или проверочная цепочка;
- получены полезные измерения времени, токенов или качества;
- обнаружено ограничение, которое важно честно назвать аудитории;
- появился наглядный материал для самостоятельного поста.

Мелкие рефакторинги, единичные команды и не подтверждённые эксперименты в
журнал не записываются.

## Поток данных

После значимого результата техническая задача обновляет месячный журнал и
создаёт либо дополняет release packet. Если результат имеет самостоятельный
сюжет, он добавляется в очередь тем. Telegram-редактор начинает работу с
`docs/telegram/START_HERE.md`, выбирает готовую тему, проверяет доказательства и
создаёт черновик. Публикация без отдельного разрешения пользователя запрещена.

## Безопасность и достоверность

- Не сохранять API-ключи, пароли, SSH-реквизиты, приватные IP и полные логи с
  персональными данными.
- Не выдавать план или прототип за выпущенную возможность.
- Числа брать только из сохранённого прогона, теста или журнала.
- Ограничения сообщать так же явно, как успехи.
- Ссылку «попробовать» добавлять только после проверки её доступности.

## Критерии готовности

- Новая редакторская задача может понять текущее состояние, открыв один файл.
- По последнему успешному прогону есть заполненный release packet.
- Есть очередь минимум из пяти доказуемых тем.
- Установлено правило обновления после значимых технических результатов.
- Ни один файл редакторского контура не содержит секретов.
