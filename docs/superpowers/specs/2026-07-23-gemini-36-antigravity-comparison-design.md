# Kaigo: сравнение Gemini 3.6 Direct и Antigravity

Дата: 2026-07-23

## 1. Цель

Провести воспроизводимый эксперимент на одном и том же задании для RAW BUREAU:

1. сохранить текущую версию на Gemini 2.5 Flash как baseline;
2. создать новый вариант прямой цепочкой на Gemini 3.6 Flash;
3. создать отдельный вариант управляемым агентом Antigravity;
4. опубликовать все варианты рядом с отчётом, ревизиями и доказательствами;
5. проверить опубликованный результат во встроенном браузере Codex.

Эксперимент отвечает на практический вопрос: насколько новые модели и готовый
агентный harness улучшают внешний вид, функциональность и процесс создания
виджета по сравнению с текущей цепочкой.

## 2. Границы ближайшей реализации

Сейчас реализуются только:

- миграция моделей и параметров Gemini;
- поддержка свободного JavaScript в экспериментальном артефакте;
- снятие продуктовых ограничений с CSS-анимаций;
- поэтапные краткие отчёты модели;
- адаптивный сбор исходного сайта;
- расширенный визуальный и функциональный аудит;
- два новых прогона и страница сравнения;
- архивирование baseline.

Автоматический compiler системного prompt сотрудника и независимый строгий
code reviewer фиксируются как следующая итерация и не меняют входные данные
этого сравнения.

## 3. Матрица моделей

| Компонент | Модель | Thinking |
| --- | --- | --- |
| Direct: направления, судья и пять ревизий | `gemini-3.6-flash` | `high` |
| Анализ исходного сайта | `gemini-3.5-flash` | `high` |
| Визуальный критик | `gemini-3.5-flash` | `high` |
| Чат посетителя | `gemini-3.5-flash-lite` | `medium` |
| Agent build | `antigravity-preview-05-2026` | Gemini 3.6 Flash, агентный цикл |

Для Gemini 3.6 Flash и Gemini 3.5 Flash-Lite из запросов удаляются
`temperature`, `top_p` и `top_k`. Вместо них передаётся `thinking_level`.
Конфигурация должна хранить thinking отдельно для builder, analyzer, critic и
chat, чтобы назначения моделей не были связаны одним общим значением.

Antigravity получает явный общий token budget и deadline. Отчёт сохраняет
фактически использованные модель, токены, время, количество шагов и итоговый
статус взаимодействия.

## 4. Неизменяемый пакет сравнения

Перед первым новым прогоном создаётся versioned input bundle:

- исходный brief RAW BUREAU без переформулирования;
- исходный URL;
- подтверждённые публичные факты;
- извлечённые visual tokens;
- одинаковые исходные desktop/mobile screenshots;
- существующий chat system prompt;
- одинаковые viewport и критерии приёмки;
- версии schema, runtime и validators;
- дата и digest каждого входного файла.

Обе новые ветки получают копию одного bundle. После начала первого прогона
bundle не изменяется. Сравнение использует пользовательский профиль
`20 минут / максимальное качество`; одинаковое число внутренних API-вызовов не
требуется, поскольку Direct и Antigravity устроены по-разному.

## 5. Baseline

Текущий результат сохраняется до миграции:

- полный JSON запроса и ответа;
- HTML, CSS и chat prompt;
- модель, usage и elapsed time;
- все текущие browser-audit screenshots;
- отчёт валидаторов;
- source screenshots RAW BUREAU;
- короткое описание известных недостатков.

Baseline остаётся доступным по отдельному неизменяемому URL и не
перезаписывается новыми генерациями.

## 6. Direct-цепочка

Direct сохраняет текущую структуру:

1. три независимых предложения направления;
2. blind judge;
3. `art_direction`;
4. `foundation`;
5. `identity`;
6. `conversation`;
7. `motion_polish`;
8. deterministic validation и repair;
9. browser audit;
10. visual critique и при необходимости visual repair.

После каждого принятого этапа артефакт коммитится как отдельная ревизия и
немедленно передаётся в preview через существующие SSE-события.

В `WidgetArtifact` добавляются:

- `change_summary` — одно-два коротких предложения о реальном изменении;
- `javascript` — свободный JavaScript текущей ревизии;
- `layout_contract` — выбранные моделью размеры и responsive-параметры.

UI показывает `change_summary` рядом с номером этапа, а также вычисленный
сервером diff полей HTML, CSS, JavaScript и layout. Текст модели не считается
доказательством без фактического изменения артефакта.

## 7. Antigravity-цепочка

Antigravity получает в удалённую песочницу:

- тот же immutable bundle;
- artifact schema;
- задачу и критерии приёмки;
- trusted preview runtime;
- локальные валидаторы;
- browser-audit command;
- инструкцию сохранить полный финальный артефакт и краткий журнал изменений.

Агенту разрешено самостоятельно создавать и редактировать файлы, запускать
проверки и повторять цикл исправлений. Результат принимается только после
преобразования в тот же `WidgetArtifact`, который использует Direct.

Antigravity не обязан повторять пять стадий Direct. Для сравнения фиксируются
его собственные шаги, tool calls, проверки, время и стоимость.

## 8. Свободный JavaScript

В исследовательском режиме модель не ограничивается каталогом готовых
сценариев. Она может создавать любой JavaScript, необходимый для:

- открытия и закрытия;
- таймеров и scroll-trigger;
- реакции на видимость или клик элементов;
- сложных анимаций;
- динамического DOM;
- вычисления размеров и состояний;
- любых других предложенных ею взаимодействий.

JavaScript хранится отдельным полем артефакта и выполняется внутри preview
виджета. Ограничения `script`, inline handlers и произвольных DOM-событий в
валидаторе снимаются.

Единственная инфраструктурная граница: экспериментальный код остаётся внутри
изолированного iframe и не получает секреты сервера. Это не ограничивает
творческую логику виджета, но не позволяет одной неудачной генерации уничтожить
Builder или раскрыть API key.

Функциональный аудит наблюдает console errors, unhandled rejections, сетевые
запросы, навигацию, зависшие таймеры и итоговые изменения DOM. На первом этапе
эти данные являются отчётом и основанием для сравнения, а не blanket-запретом.

## 9. Анимации

Для экспериментальных прогонов снимаются ограничения на:

- число `@keyframes`;
- длительность;
- `animation-iteration-count`;
- `infinite`;
- набор анимируемых свойств.

`prefers-reduced-motion` остаётся рекомендацией модели, но его отсутствие не
блокирует исследовательскую генерацию.

Чтобы получить стабильные доказательства, browser audit перед измерением
создаёт обычный кадр с активным motion, затем отдельный settled-кадр, в котором
анимации программно фиксируются. Аудит записывает количество активных
анимаций, long tasks и ошибки, но не отклоняет вариант только из-за сложного
motion.

## 10. Размеры и объём артефакта

Жёсткие размеры `216×46px` и `372px` удаляются из prompt и release gate.
Модель выбирает размеры внутри общих продуктовых диапазонов и записывает их в
`layout_contract`.

Проверяются:

- launcher высотой не меньше 44px;
- desktop panel ориентировочно 320–440px, если brief не обосновывает иное;
- отсутствие перекрытия критических controls;
- отсутствие horizontal overflow;
- доступность close/send;
- mobile safe area и отсутствие непреднамеренного fullscreen;
- фактическая площадь относительно host viewport.

Лимиты 64 KiB HTML и 96 KiB CSS сохраняются. Baseline использует только
1.7 KiB HTML и 5.9 KiB CSS, поэтому эти лимиты сейчас не ограничивают
творчество. Для JavaScript вводится отдельный достаточно высокий технический
лимит, который защищает только транспорт и хранение, а не стиль реализации.

## 11. Анализ исходного сайта

Crawler переходит от одной фиксированной паузы к адаптивной стабилизации:

- увеличенный initial warm-up;
- пошаговый scroll;
- ожидание затишья DOM mutations и layout;
- ожидание изображений и шрифтов;
- дополнительный settle после lazy content;
- повторный кадр при изменившейся странице;
- top, middle и bottom для desktop/mobile.

В пакет исходных доказательств добавляется desktop viewport 1920×1080.
Существующие 1440×900 и 390×844 сохраняются для совместимости и mobile.

## 12. Аудит и screenshots

Для каждого варианта создаются:

- 1920×1080 host-context: closed;
- 1920×1080 host-context: open;
- 1920×1080 host-context: после двух сообщений;
- крупный crop launcher;
- крупный crop открытого panel;
- увеличенный crop мелких деталей;
- mobile closed/open/after-chat;
- кадр с активным motion;
- settled-кадр для точной геометрии.

Функциональный аудит проверяет реальными действиями:

- pointer и keyboard open/close;
- Enter и send button;
- две последовательные реплики;
- сохранение истории и draft;
- suggestions;
- scroll истории;
- retry после ошибки;
- console и network;
- отсутствие необъяснимо неработающих controls.

Host-context строится на сохранённом визуальном состоянии RAW BUREAU, а
функциональные проверки выполняются в контролируемой fixture. Так внешний сайт
не делает тест недетерминированным, но визуальный критик видит реальный масштаб.

## 13. Публикация и отчёт

Публикуются:

- `/builder-demo/compare/`;
- `/builder-demo/archive/raw-bureau-v1/`;
- `/builder-demo/direct-3-6/`;
- `/builder-demo/antigravity-3-6/`.

Страница сравнения показывает:

- три интерактивных варианта;
- входной brief и digest bundle;
- модель и thinking;
- стадии или агентные шаги;
- summaries и ревизии;
- screenshots;
- validator/browser/visual findings;
- usage, elapsed time и оценку стоимости;
- известные ошибки и ограничения.

Финальная проверка выполняется во встроенном браузере Codex на desktop и
mobile viewport. Публичная публикация считается завершённой только после
реального двухходового разговора с каждым новым виджетом.

## 14. Следующие итерации

После сравнения отдельно проектируются и реализуются:

1. автоматический compiler system prompt сотрудника из подтверждённых фактов,
   тона бренда, доступных действий и контекста страницы;
2. независимый строгий reviewer, который получает brief, before/after code,
   screenshots и проверки и возвращает `blocker`, `warning`, `nit`;
3. пользовательские режимы создания `5`, `10` и `20` минут с возможностью
   продолжить улучшение существующего результата;
4. перенос проверенных интерактивных идей из свободного JavaScript в
   продуктовый runtime после накопления реальных примеров.

## 15. Критерии завершения эксперимента

Эксперимент завершён, когда:

- baseline сохранён и открывается;
- Direct реально использует Gemini 3.6 Flash/high;
- critic и analyzer используют Gemini 3.5 Flash/high;
- chat использует Gemini 3.5 Flash-Lite/medium;
- Antigravity завершил отдельный реальный агентный прогон;
- оба новых варианта получили один immutable input bundle;
- поэтапные summaries и ревизии доступны;
- свободный JavaScript и unrestricted CSS motion исполняются в preview;
- опубликованы отчёт и все три варианта;
- обе новые версии прошли реальный браузерный двухходовый чат;
- Git содержит спецификацию, реализацию и воспроизводимые доказательства.
