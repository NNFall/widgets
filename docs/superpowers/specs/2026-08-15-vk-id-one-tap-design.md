# VK ID One Tap — дизайн интеграции

**Дата:** 2026-08-15  
**Статус:** утверждено пользователем

## Цель

Добавить VK ID как третий способ входа в существующее окно авторизации Kaigo, не ломая Google, Яндекс, сохранение анонимного черновика и последующее открытие Студии.

Пользователь видит одну официальную синюю строку «Войти с VK ID». Быстрый персонализированный текст «Продолжить как …» и альтернативный вход внутри VK-виджета отключены.

## Пользовательский сценарий

1. Пользователь приходит с лендинга в Студию, при необходимости с уже сохранённым черновиком.
2. В окне входа рядом с Google и Яндексом отображается официальный VK ID One Tap.
3. Нажатие переводит пользователя в VK ID в той же вкладке.
4. VK возвращает одноразовый код, `state` и `device_id` на `https://kaigo.space/api/auth/vk/callback`.
5. Сервер сверяет одноразовое состояние и браузерную привязку, обменивает код по OAuth 2.1 PKCE и создаёт обычную сессию Kaigo.
6. Привязанный черновик сохраняется и открывается как проект тем же способом, что после Google или Яндекса.
7. Если официальный виджет не загрузился, интерфейс показывает обычную ссылку «Войти с VK ID», которая запускает тот же серверный OAuth-поток.

## Интерфейс

- Официальный `@vkid/sdk`, закреплённая версия пакета.
- `OneTap` с `fastAuthEnabled: false` и `showAlternativeLogin: false`.
- Светлая тема, основной скин, высота 44 px, радиус 8 px, ширина контейнера.
- Внутренности cross-origin iframe не изменяются пользовательским CSS.
- Google и Яндекс остаются доступными и визуально не меняются.
- При ошибке SDK пользователь получает безопасный fallback без технических деталей и без потери черновика.

## Серверная архитектура

### Конфигурация

Kaigo получает только публичный `VK_OAUTH_APP_ID`. Защищённый и сервисный ключи для выбранного PKCE-потока не используются, не хранятся в репозитории и не передаются браузеру.

### Bootstrap

`POST /api/auth/vk/bootstrap` создаёт ту же одноразовую OAuth-транзакцию, что существующий `/api/auth/{provider}/start`, включая:

- rate limit;
- browser binding в зашифрованной сессии;
- одноразовый `state` с хешем в БД;
- PKCE verifier/challenge;
- привязку ожидающего черновика и funnel journey;
- короткий срок действия.

В ответ браузер получает только публичные и одноразовые поля: `app_id`, `redirect_uri`, `state`, `code_verifier`. Ответ имеет `Cache-Control: no-store`.

### Callback и обмен кода

Сервер принимает `code`, `state`, `device_id`, одноразово погашает сохранённое состояние до сетевого обмена, затем:

1. отправляет код и PKCE verifier в VK token endpoint;
2. требует совпадения `state` в ответе;
3. получает профиль через VK user-info endpoint;
4. требует стабильный VK user id и email;
5. нормализует имя и avatar в безопасный публичный профиль;
6. использует существующий общий код создания пользователя, identity, сессии и claim черновика.

VK access/refresh tokens не сохраняются в браузере, сессии или БД Kaigo.

## Безопасность и приватность

- OAuth 2.1 Authorization Code + PKCE, одноразовый `state`, browser binding, TTL и rate limit.
- Только scope `email`.
- Никаких OAuth-секретов во frontend bundle, ответах API, логах, документации или Git.
- CSP разрешает `connect-src https://id.vk.ru` и `frame-src https://id.vk.ru`, но сохраняет `script-src 'self'`.
- MyTracker и другие дополнительные сторонние скрипты не разрешаются автоматически.
- Все ошибки пользователю маппятся на существующие безопасные русские сообщения.

## Отказоустойчивость

- Недоступный SDK не скрывает Google/Яндекс и заменяется обычной VK-ссылкой.
- Повторный callback не может повторно использовать OAuth state.
- Неверный/missing `device_id`, state, email или VK subject отклоняется.
- Отмена на стороне VK возвращает пользователя к окну выбора входа.

## Проверка готовности

- Unit-тесты VK provider: URL, PKCE, `device_id`, state, token/user-info, ошибки.
- Route-тесты: bootstrap, draft binding, no-store, callback, replay, session providers.
- Frontend-тесты: параметры OneTap, один ряд, fallback и сохранение draft id.
- CSP/deployment-тесты: только `id.vk.ru` в frame/connect, без ослабления script policy.
- Полные focused backend/frontend suites, typecheck, lint, build и визуальный browser smoke.
- На production подтверждаются Google/Яндекс и появление VK One Tap. Полный VK callback считается подтверждённым только после реального входа владельца аккаунта.
