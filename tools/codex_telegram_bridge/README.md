# Telegram ↔ Codex для Windows

Этот мост позволяет писать в Telegram и продолжать ту же задачу Codex, которая открывается
в Desktop-приложении. Он использует официальную CLI-команду `codex exec resume`; JSONL истории вручную
не редактируется.

Первая версия принимает только текст. Она не публикует посты в канал автоматически и не
обходит правило явного утверждения.

## Что нужно

- Windows 10/11 и PowerShell 5.1 или новее.
- Python 3.11 или новее, доступный как `python.exe`.
- Codex CLI, в котором уже выполнен вход.
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).
- Telegram user ID владельца и ID нужной задачи Codex.

ID этой задачи Telegram-редактора:

```text
019f9e1b-fb04-7482-b62d-cee4c051131b
```

## Первая настройка

Откройте PowerShell обычного Windows-пользователя, перейдите в корень репозитория и запустите:

```powershell
& .\tools\codex_telegram_bridge\setup.ps1
```

Мастер попросит:

1. Токен от BotFather. Ввод скрыт.
2. Telegram user ID. Только этот пользователь сможет запускать Codex.
3. Telegram chat ID. В личном чате с ботом обычно достаточно нажать Enter и взять user ID.
4. ID задачи Codex.

Токен сохраняется в переменной среды `TELEGRAM_BOT_TOKEN` текущего Windows-пользователя.
Несекретная конфигурация появится в:

```text
%LOCALAPPDATA%\KaigoCodexTelegramBridge\config.json
```

## Ручной запуск и проверка

```powershell
& .\tools\codex_telegram_bridge\run.ps1
```

После запуска откройте бота в Telegram:

```text
/start
/status
/thread
/previous
```

Любой обычный текст попадёт в привязанную задачу Codex. Бот сначала подтвердит очередь, а потом
вернёт финальный ответ. В Codex Desktop новый ход может появиться после переоткрытия или перезапуска
приложения.

Команды `/previous` и `/lastpost` копируют последний пост из настроенного публичного канала в
личный чат. Telegram сохраняет форматирование, фотографию и подпись. Для альбомов реестр может
хранить массив `telegram_message_ids`, и сообщения копируются в исходном порядке. Команда ничего
не публикует и не запускает Codex.

## Переключение между задачами

Код менять не нужно. Разрешённый пользователь может написать:

```text
/use 00000000-0000-0000-0000-000000000000
```

Следующее сообщение пойдёт в новую привязку. Привязка хранится в SQLite и переживает перезапуск.

## Автозапуск при входе в Windows

```powershell
& .\tools\codex_telegram_bridge\install-startup-task.ps1
Start-ScheduledTask -TaskName "Kaigo Codex Telegram Bridge"
```

Скрипт создаёт Scheduled Task только для текущего пользователя, с уровнем `Limited`. Права
администратора не требуются.

Удалить автозапуск:

```powershell
& .\tools\codex_telegram_bridge\uninstall-startup-task.ps1
```

## Очередь, перезапуск и логи

Мост выполняет только один ход Codex за раз. Следующие сообщения ждут в SQLite-очереди. После сбоя:

- незавершённый ход возвращается в очередь;
- уже сгенерированный outbox-ответ не вызывает Codex заново, а записывается в SQLite и
  отправляется в Telegram;
- повторный Telegram `update_id` не создаёт второй ход.
- частичная отправка длинного ответа продолжается с последнего подтверждённого фрагмента.

Второй экземпляр с тем же data directory завершится сразу, в том числе из другой
RDP-сессии Windows. Это защищает историю Codex от одновременного запуска двух
worker-процессов.

Файлы находятся в `%LOCALAPPDATA%\KaigoCodexTelegramBridge`:

- `bridge.sqlite3` — очередь и привязки;
- `bridge.log` — локальный технический лог;
- `codex-output` — устойчивый outbox на коротком участке между завершением Codex и
  подтверждённой записью в SQLite; после записи файл удаляется.

Токен бота и полные тексты Telegram-сообщений в лог не пишутся.
После успешной доставки prompt и response очищаются из очереди. Каждый час завершённые
служебные записи старше 30 дней удаляются, а освобождённые страницы SQLite очищаются.

## Понятные ограничения

- Telegram может хранить неполученные Bot API updates не более 24 часов.
- `getUpdates` не работает, пока у того же бота установлен webhook.
- Входящие фото, голосовые сообщения и inline-кнопки пока не передаются в Codex. `/previous`
  при этом умеет показать уже опубликованный пост с фотографией.
- Ошибка WebSocket 403 в выводе Codex может быть некритичной: CLI переходит на HTTPS. Мост считает ход
  успешным по exit code 0 и наличию финального output file.
- Telegram `sendMessage` не поддерживает ключ идемпотентности. После обычной сетевой
  ошибки cursor исключает повтор уже подтверждённых частей; после жёсткого crash точно
  между отправкой и сохранением cursor может повториться один фрагмент.
